Proof lane A

One fixture. Bad source and current source.

The original diagnostic observes the bug

It exits successfully when replay wrongly throws “Package artifact changed.” Derive a portable fixture, retain its diff, and invert that final expectation to require correct behavior.

Keep the current broad choreography test as the modern regression gate. Its newer recovery segment makes it unsuitable unchanged on the historical revision.

A setup failure proves no defect

The old run must fail at the saved-replay assertion after setup succeeds. Import errors, timeouts, zero tests and unrelated failures do not count.

One classified historical-build environment repair is allowed. A reviewed historical-source transplant is a possible revised method, with its own explicit label and limits.

Isolation, binary binding and fixed budgets

Freeze exact old/new patch text, hashes and the source preimage. Patch one file at a time in a disposable checkout. Refuse mismatch, multiple replacement matches or any path outside that module. Restore and hash the baseline between trials.

The native adapter loads target/debug/examples/repository-fixture relative to its working directory. Run from the trial checkout; rebuild and fingerprint its own binary for every mutant. Build both --bin crewroom-process and --example repository-fixture for the baseline.

  • Baseline setup/build: at most 10 minutes.
  • Each later build: at most 3 minutes; each selected test: at most 45 seconds.
  • Total: at most 30 minutes; at most two useful assertion improvements.

Lockfile-identical dependency reuse may be recorded. Main’s executable is not a substitute for the trial binary.

Ordered implementation

Six gates before FOR-13 can close

  1. Resolve the sources

    Refresh Linear and FOR-12 completion. Preserve both occurrence sources and the original MH6 diagnostic. Review independence and common cause.

    Gate: two authentic distinct occurrences, or an explicitly incomplete claim.

  2. Write the record contract

    Create the correction record as unverified. Implement bounded reference validation and separate recurrence, enforcement and disposition facts.

    Gate: missing, duplicate, one-off or judgment evidence cannot become false proof.

  3. Prove existing enforcement

    Run the minimal fixture on old and current source, then the current regression. Capture legitimate success, causal failure and changed-payload refusal.

    Gate: exact source, binary, test and cleanup identities for both runs.

  4. Run the fixed mutation trial

    Build the baseline, execute the five isolated patches, classify outcomes and improve only demonstrated missing assertions within the budget.

    Gate: full matrix, costs and independent survivor assessment; no score target.

  5. Preserve existing authority

    Verify tools leave app configuration, workflow database, queue and main source unchanged. S7 still owns proposal review and operator decisions.

    Gate: no adoption, admission or execution inferred from a validated record.

  6. Review and close with evidence

    Trace each acceptance item independently. Run applicable checks, commit revision-bound evidence, sync status/progress and verify Linear.

    Gate: Done only after acceptance. FOR-14 stays separate.

Stop rather than erase uncertainty

Preserve the failure and classify its cause before another attempt. After two unsuccessful reruns of the same classified failure, stop that lane; new runs need new evidence or a revised testing decision.

The historical build has its narrower one-repair limit. Mutation timeouts stop at their fixed budgets. An unresolved owned child makes the attempt incomplete.

No extra acceptance claims

No paid model calls, repeated MH6 live jobs, live Jira/PR delivery, platform/package/terminal certification, full state restore or FOR-14 instruction comparison.

Zero tests, zero exercised viable mutants, unclassified survivors or unfinished required runs cannot close the trial. A quiet terminal is never a gate.

Small interface, existing authority

Record facts without creating another workflow

The validator proves a bounded claim

Resolve fixed Git references or retained private paths beneath an explicit evidence root. Check source hashes and bounded extraction; reject traversal, ambiguity and unsupported fields.

Keep reference resolution, recurrence assessment, enforcement proof and proposal disposition separate. Mechanical validity still requires semantic review, bound to the canonical claim and source/proof hashes. Edits invalidate that review.

Proposed outcomes: verified, incomplete, invalid. Missing evidence stays visible; a one-off cannot satisfy the recurrence gate.

S7 keeps approval and provenance

The chosen class records existing_enforcement_reused. No ceremonial proposal or new enforcement ticket is needed.

Judgment-dependent guidance stays “recommended, not submitted” until a real S7 proposal exists. Approval remains an operator decision; admitted assignments retain their captured instructions.

Historical repository review files are not product evidence IDs. Do not forge a run, citation or operator decision. Schema remains 29.
