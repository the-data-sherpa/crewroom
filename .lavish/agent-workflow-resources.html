First experiment

A verification map agents can use

Connect one operator-visible feature to prerequisites, actual user actions, expected outcomes and existing verification commands.

Reuse the scenario and journey records. Native flow proof must identify platform, revision and actual surface exercised.

High value

Corrections become checks

For a recurring failure, choose the strongest practical remedy: architecture, types, static check, behavioral test, or guidance requiring judgment.

Prove the check catches a real mistake and permits valid behavior. Structural changes remain scoped repository work.

Bounded follow-up

Compare instruction revisions

Give old and proposed role instructions the same cases. Inspect actual artifacts and tool use; keep scoring criteria outside worker prompts.

This comes from pstack’s eval playbook. No automatic promotion or new release gate is proposed.

Preserve

Human merge and durable requirements

Automatic merging and ephemeral specifications do not fit Crewroom’s current contract. Neither does automatic backlog intake.

Keep operator-queued work, bounded concurrency, recoverable history and independent processes.
