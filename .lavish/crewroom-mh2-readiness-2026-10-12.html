Information still needed

Three experiments determine the implementation.

01

Can every action stay inside Crewroom’s tool controls?

Capture the actual offered tools. Exercise native command, patch, network, plugin and subagent paths deliberately. Feature flags and a read-only sandbox have not established complete confinement.

02

Do Codex’s real requests fit the provider gateway?

Verify model/effort, full history, tool shapes, retries, compaction and usage. The gateway currently accepts a narrower Responses request shape than Codex may send. Preserve its guards; change only what evidence justifies.

03

Can restart preserve a tool effect without repeating it?

Persist input, thread, turn, call and original-operation mappings. Crash around admission, side effect, result persistence and reply. Reconcile the original receipt before any redelivery.

Observed recovery edge case: the non-inference probe received a thread ID and rollout path, but immediate and restarted resume both returned “no rollout found.” The first durable-history boundary still needs a disposable turn.

Implementation details retained in the brief.

Migration and identity

Read untagged historical records as OMP, preserve existing provider/model strings and session/ownership paths, and reject unknown explicit adapter tags. New Codex records need generic runner identity; do not place its PID under ompPid. Update launch, stop, store validation and terminal observation together.

Replay and failure behavior

A server RPC request ID and a logical tool-call ID are different facts. Backend deduplication is currently often scoped to attempt plus call. A replacement attempt needs the original operation/receipt mapping; uncertainty must stay visible until reconciled. Interrupted turns, failed turns and stopped OS ownership are also separate observations.

Required acceptance coverage

Exact model/effort; addressed tools and external Mail; wrong/stopped caller denial; busy steering; pause during streaming and contained tools; daemon reattachment and runner replacement; tool replay crash points; usage/active-time limits; and legacy OMP recovery. Run the relevant Rust and native tests plus domain, build and user-flow checks against the implementation revision.
