Ordered implementation with parallel specialists

Six gates before FOR-14 can close

  1. Domain and security contract

    Freeze manifest/cell identities, migration, internal projections, two-actor admission and shared ownership/capabilities.

    Gate: schema-29 state preserved; unknown purpose denied; no new authority.

  2. Fixtures and artifact scoring

    A specialist builds four ordinary tasks and private oracles while runtime work adds frozen admission and evaluation receipts.

    Gate: valid work accepted; stale, skipped and wrong-surface evidence rejected; no rubric leak.

  3. Supervision and recovery

    Serialize cells under the existing writer gate. Retain budgets, frozen route, pause intent and replayable results.

    Gate: restart/stop/provider faults cannot duplicate work or erase outcomes.

  4. All three native editor paths

    A UI specialist works against the agreed API. Add result inspection, historical binding and existing explicit decisions.

    Gate: role/principle/playbook flows work; direct ordinary Save stays available.

  5. Real runner and live proof

    Check changed tools, run the 16-worker matrix through the product path and separately demonstrate live supervision recovery.

    Gate: actual live behavior plus retained receipts and owned cleanup; no winner required.

  6. Independent review and handoff

    A fresh reviewer checks scope, security, coverage and source/evidence bindings. Update status, progress and Linear.

    Gate: verified acceptance and exact commits before Done.

Parallel work owns disjoint files after the shared contract is agreed. Evaluated repository writers remain serial. Test each slice before advancing.
