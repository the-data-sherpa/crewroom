# NTM: queue, workflow gates, and PR/CI fit

Researched 2026-09-25. Read-only, targeted source inspection; no installation, runtime test, or broad code audit. Current main was pinned to [`69c7195e2cee00d33f6c27bb9d768568aa254f0f`](https://github.com/Dicklesworthstone/ntm/commit/69c7195e2cee00d33f6c27bb9d768568aa254f0f). Release `v1.35.1` resolves to [`74ceb3236416f503797344a5a8a8d94ee061f584`](https://github.com/Dicklesworthstone/ntm/commit/74ceb3236416f503797344a5a8a8d94ee061f584).

## Supported conclusion

NTM supplies real queue dispatch, assignment bookkeeping, and configurable workflow execution. It is a plausible foundation for visible, independent tmux agents. The inspected defaults do **not** implement the complete contract “research → implement → independent review → tests/regressions → docs → PR → next task.” Configuring those stages, their evidence, their dependencies, and the PR provider remains necessary. In particular, task closure and an agent returning to idle are not verified software-quality outcomes. Shell stages can supply actual exit-code gates. [Assignment implementation](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/coordinator/assign.go#L92), [pipeline executor](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/pipeline/executor.go#L1738).

## Observed in code

- **Real auto-assignment, opt-in.** The coordinator periodically refreshes state and dispatches actionable `bv` recommendations. It checks live work eligibility, avoids occupied assignments, and scores agent/task matches. With `assign_only_idle`, it requires fresh, healthy, safely dispatchable idle observations; otherwise it can queue Agent Mail work to busy agents. This is substantially more than an instruction telling a lead agent to delegate. [Assignment selection](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/coordinator/assign.go#L92), [eligibility and polling](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/coordinator/coordinator.go#L382), [default disabled](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/coordinator/coordinator.go#L201).
- **Queue completion trusts tracker closure.** Reconciliation turns a delivered assignment into `completed` when `br`/`bv` reports the bead `closed`; the next cycle can assign newly actionable work. The generated worker message says “Implement and test,” then `br close`, then commit. This path does not require review approval, a test-process result, a docs artifact, or a PR before freeing the assignment. [Terminal reconciliation](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/coordinator/assign.go#L715), [assignment prompt](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/coordinator/assign.go#L1551).
- **Agent pipeline “completion” is a transport/activity condition.** Main verifies submission, requires fresh nonempty output that is not merely the prompt echo, and waits for three consecutive idle observations. It then marks the step completed. This does not inspect whether tests passed or whether the requested work succeeded. Output-parsing failure is recorded but still returns `StatusCompleted`. [Delivery and completion](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/pipeline/executor.go#L1827), [parse behavior](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/pipeline/executor.go#L1916), [idle detector](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/pipeline/executor.go#L2994).
- **Actual test gates are available.** Ordinary `command` steps run a shell process and fail on a nonzero exit. Dependent steps are skipped after dependency failure. `wait: none` instead completes after process start; `on_success` hooks explicitly do not flip the parent's status if they fail. Thus mandatory tests belong in normal dependent command steps, not fire-and-forget commands or success hooks. The separate workflow engine also implements real `command_success` triggers, used by the built-in red/green workflow for `go test ./...`. [Command result](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/pipeline/executor.go#L1524), [dependencies and hooks](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/pipeline/executor.go#L892), [fire-and-forget](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/pipeline/executor.go#L1387), [command trigger](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/workflow/trigger.go#L393), [red-green template](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/workflow/builtins/red-green.toml).
- **Review orchestration exists, but approval is agent text.** The built-in `review-pipeline` configures one author and two reviewers, manual submission/resubmission, and reviewer output matching `approved|lgtm|looks good` to finish. Default approval mode is `any`; code supports `all`/quorum and validates reviewer identities. This provides separate review roles, not a verified external PR review record. `review-queue` is a separate command that suggests/sends review prompts to idle agents; it is not inherently a mandatory gate before closing a task. [Review template](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/workflow/builtins/review-pipeline.toml), [regex trigger](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/workflow/trigger.go#L435), [approval counting](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/workflow/coordinator.go#L384), [review-queue surface](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/cli/review_queue.go#L64).

## PR/CI and Bitbucket

I could not verify a built-in PR-creation/CI-status provider for either Bitbucket or GitHub in the inspected README, command registration, robot declarations, pipeline schema, and git/repo/worktree commands. The observed git surface provides coordination, sync, and worktree operations. It would be inaccurate to call NTM's PR integration “GitHub-only” on this evidence. Generic command steps could call a Bitbucket CLI/API or a project script, but that is a configured integration, not a verified turnkey feature. This is a bounded negative finding, not proof no extension exists anywhere. [Command registration](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/cli/root.go#L5148), [git commands](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/cli/git.go#L18), [repo passthrough](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/cli/repo.go#L13), [command step schema](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/pipeline/schema.go#L365).

## Documentation versus runtime and release caveat

Documentation provides design/implement/test and implement/review/revise examples, but its test-verification example is an **agent prompt** asking the agent to run/fix tests. That example alone is not an exit-code gate. Likewise `work impact` analyzes issues affected by file paths; it is not itself a mandatory impact-research stage. [Workflow example](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/docs/WORKFLOW_EXAMPLES.md#L95), [impact command](https://github.com/Dicklesworthstone/ntm/blob/69c7195e2cee00d33f6c27bb9d768568aa254f0f/internal/cli/work.go#L213).

Core auto-assignment, tracker-closure reconciliation, command exit-code handling, and the review template already exist in `v1.35.1`. The current-main durable agent-delivery record and fresh non-echo output requirement are newer: the release executor verifies submission then waits for stable idle without that delivery-evidence callback. Do not assume all main-branch safeguards ship in the release binary.
