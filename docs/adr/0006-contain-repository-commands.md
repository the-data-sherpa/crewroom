# Contain repository commands separately from the visible agents

M2.3 exposed a real ownership gap: a tool descendant can detach and close an inherited lock, so a native process group cannot certify that all command work stopped. Keep each OMP agent in its own observable tmux host, disable native agent tools, and execute admitted repository commands in separate Docker containers whose durable identities Crewroom reconciles through the local engine socket. The container test stops a detached child even after it clears its environment and descriptors; loss of engine control remains uncertain and blocks replacement.

This is an implementation decision from the authorized interruption gate, not a change to the product scope or the selected OMP/tmux/Rust Mail communication stack. Images are pinned and provisioned separately; commands receive only their workspace mount, no host credentials or engine socket, no network, and no added capabilities. A Linux command environment is now required for repository checks; selecting and verifying the the pilot repository image remains part of onboarding. The small inherited-lock helper remains useful for known host/runner processes and exclusive backend ownership, but it is not the safety boundary for arbitrary commands.

Evidence: [M2.3 execution record](../testing/mvp-progress.md#m23--safe-interruption-and-ownership), `tests/container.integration.ts`, and the application interruption fixture. Docker documents its [namespace isolation](https://docs.docker.com/engine/security/) and [container termination](https://docs.docker.com/reference/cli/docker/container/kill/); the actual escaped-child test supplies the application evidence. Apple's [process-event definitions](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/event.h) mark automatic child tracking unsupported, so a native polling workaround was not accepted as proof.
